# Plan: Working .deb package for YACReader (TDD)

## Goal

Produce a working `.deb` package of YACReader (version from `VERSION`, currently `10.6.0`)
that installs and runs on **this system**: Linux Mint 22.3 ("Zena") — a Ubuntu 24.04
(noble) base with distro Qt 6.4.2, distro poppler 24.02 and the distro `7zip` runtime.

Starting point: `build_scripts/ubuntu_24.04/` — its build config is mirrored:
Qt 6, `DECOMPRESSION_BACKEND=7zip` (RAR5 capable `7z.so` shipped by the package),
`PDF_BACKEND=poppler`.

## Test-first approach (e2e)

The e2e test is written **before** any packaging code, and must fail first:

`build_scripts/ubuntu_24.04/e2e_deb_test.sh`

It verifies, in order:

1. **Package sanity** — a `.deb` exists in `build_scripts/ubuntu_24.04/dist/`,
   `dpkg-deb --info` parses it, package name `yacreader`, version matches `VERSION`.
2. **Install** — `apt-get install ./dist/yacreader_*.deb` succeeds
   (auto-resolves dependencies), `dpkg -s yacreader` reports `installed`.
3. **Files present** — the three binaries (`/usr/bin/YACReader`,
   `/usr/bin/YACReaderLibrary`, `/usr/bin/YACReaderLibraryServer`), desktop files,
   icons, man pages, server web assets and the bundled `/usr/lib/*/yacreader/7z.so`.
4. **Runs without crashing (headless)** — each of these must exit 0, no SIGSEGV:
   - `YACReaderLibraryServer --version`
   - `YACReaderLibraryServer --system-info`
   - `YACReaderLibraryServer list-libraries` (isolated `HOME`/`XDG_*`)
   - `QT_QPA_PLATFORM=offscreen YACReader --help`
   - `QT_QPA_PLATFORM=offscreen YACReaderLibrary --help`
5. **Real startup** — `QT_QPA_PLATFORM=offscreen YACReader <sample.cbz>` is left
   running for ~5 s: process must still be alive (i.e. the GUI started, archive
   opened through the 7zip backend) and is then terminated cleanly.
6. **Uninstall** — `apt-get remove -y yacreader` leaves no binaries behind and
   `dpkg -s yacreader` reports the package as removed.

A fixture `sample.cbz` (zip of tiny PNG pages) is generated by the test itself.

## Packaging design (final)

Key constraint discovered during implementation: the GUI (develop branch) needs
**Qt >= 6.9** — the 3D coverflow is RHI-based (`rhi/qrhi.h`) and was written for
Qt 6.7+ — while this system (Ubuntu 24.04 / Mint 22.x base) ships Qt 6.4 in its
repositories. Bundling the **official Qt 6.9 LTS binaries** (glibc-compatible,
built for Ubuntu 22.04+) is therefore required for a GUI build that runs here.

* Self-contained binary package `yacreader` installing to **`/opt/yacreader`**:
  * `bin/` — the three binaries + `qt.conf`, RPATH `$ORIGIN/../lib`
  * `lib/` — bundled Qt 6.9 runtime libs + bundled `7z.so` (RAR5 capable, from
    `yacreader-7z-deps`, installed as `lib/yacreader/7z.so`, the first runtime
    search path in `YACReader::load7zLibrary()`)
  * `plugins/`, `qml/` — Qt platform/imageformat/multimedia/tls plugins and
    QML modules (QtQuick Controls/Layouts/Effects/...)
  * `share/yacreader/` — server web assets and `.qm` translations
  * `etc/` — Qt settings dir
* `/usr/bin/{YACReader,YACReaderLibrary,YACReaderLibraryServer}` — thin wrappers
  to `/opt/yacreader/bin/*` (desktop files keep `Exec=YACReader`).
* System integration files in standard locations: `/usr/share/applications`
  (desktop), `/usr/share/icons/hicolor/scalable/apps` (icons),
  `/usr/share/man/man1` (man pages), `/usr/lib/systemd/user` (user unit).
* PDF support links the **system poppler** (`Depends`); its dev headers are
  fetched at *build* time via `apt-get download` + `dpkg -x` into a local
  sysroot, so no root is needed to install `-dev` packages.
* Qt itself is downloaded at build time via `aqtinstall` (through `uv`),
  official binaries for `linux_gcc_64`, Qt **6.9.3** = exactly the version
  CMakeLists requires, so the upstream source builds unpatched.
* Dependencies are computed by scanning `NEEDED` of every ELF in the staging
  tree, excluding bundled Qt libs, mapping the rest to distro packages.
* No `debian/`+debhelper: the package is assembled and built with
  `dpkg-deb --build` (needs no root, no debhelper install, no sudo).

`build_scripts/ubuntu_24.04/build_deb.sh` orchestrates everything (build is
cached between runs; Qt download ~1.5 GB happens once).

## Non-goals

* No upload/PPA packaging, no source `.dsc`/`.orig.tar` workflow (binary-only build).
* No AppImage/Flatpak.
* No `BUILD_SERVER_STANDALONE` (the GUI library app is included, matching upstream).
* No `debian/`-debhelper workflow (sudo-less, dpkg-deb based instead).
